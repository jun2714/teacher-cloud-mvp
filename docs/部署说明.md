# 教研云 · 部署说明

本地开发继续用 `6060`（前端）+ `8001`（后端）。上线不要再用 Vite 和 `runserver`。

---

## 第一次上线（推荐：一台 Linux + Docker）

准备：一台能装 Docker 的 Linux 云主机，安全组放行 **80**（有域名再放 443）。本机 Windows 不要当生产。

### 1. 把代码放到服务器

可以用 git 拉，或把项目目录拷过去（不要带 `backend/.venv`、`frontend/node_modules`）。

```bash
cd /opt/jiaoyanyun   # 路径自定
```

### 2. 写生产 `.env`

```bash
cp backend/.env.production.example backend/.env
```

必改：

| 项 | 怎么填 |
|----|--------|
| `SECRET_KEY` | `python3 -c "import secrets; print(secrets.token_urlsafe(48))"` |
| `ALLOWED_HOSTS` | 域名和/或公网 IP，逗号分隔，**不能**是 `*` |
| `CSRF_TRUSTED_ORIGINS` / `CORS_ALLOWED_ORIGINS` | 带协议，如 `http://192.168.1.10` 或 `https://jiaoyan.example.com` |
| 百炼、短信 | 把本机已能用的 `AI_*`、`SMS_*` 拷过去（密钥不要进 git） |

`DEBUG` 不用改，compose 会强制成 `0`。

### 3. 启动

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

浏览器：

| 地址 | 用途 |
|------|------|
| `http://服务器IP/` | 教师端 H5 |
| `http://服务器IP/admin/` | 管理后台 |

需要演示账号时（空库才建议跑）：

```bash
docker compose -f docker-compose.prod.yml exec backend python manage.py seed_demo
```

- 教师：`teacher` / `teacher123`
- 管理员：`admin` / `admin123456`

老师也可直接用「验证码登录/注册」，未注册手机会自动开户（初始密码 `123456`）。

### 4. 日常

```bash
# 日志
docker compose -f docker-compose.prod.yml logs -f

# 更新代码后重建
git pull
docker compose -f docker-compose.prod.yml up -d --build
```

数据在 Docker volume 里（SQLite、头像、上传文件），重建镜像不会丢。备份 volume 或拷 `/app/data`、`/app/media`。

有域名后用 certbot 上 HTTPS，并把 `.env` 里 `CSRF_TRUSTED_ORIGINS` / `CORS_ALLOWED_ORIGINS` 改成 `https://域名`。

不想用 Docker、已有 Nginx 的机器，看下面「四、不用 Docker」。

## 一、先看清现有配置（原先不对的地方）

| 问题 | 说明 | 现已处理 |
|------|------|----------|
| `README` 写后端 `8000` | 前端 Vite 代理的是 `8001`，本机若开在 `8000` 会出现 `ECONNREFUSED` | 文档已改成 `8001` |
| `docker-compose.yml` 也映射 `8000` | 和本机代理不一致 | 开发 compose 改为 `8001:8000` |
| 容器里代理 `127.0.0.1:8001` | Docker 里 `127.0.0.1` 是前端容器自己，连不到后端 | 可用环境变量 `VITE_API_PROXY=http://backend:8000` |
| 生产仍用 `runserver` + `DEBUG=1` | 不能对外提供服务 | 生产改用 gunicorn + nginx，`DEBUG=0` |
| gunicorn **不会**提供 `/static/`、`/media/` | Django 的 `static()` 只在 `DEBUG=1` 时挂路由；关 DEBUG 后头像、后台样式会 404 | nginx 直接托管 `staticfiles` 和 `media` |
| 缺 `CSRF_TRUSTED_ORIGINS` | 用域名打开 `/admin/` 登录会 403 | 已在 `settings.py` 读取该变量 |

生产架构：

```text
浏览器
  └── nginx :80
        ├── /            → 前端打包结果（Vue dist）
        ├── /api /admin  → gunicorn（Django）
        └── /static /media → 磁盘文件（不要再走 Django）
```

## 二、环境变量

复制 `backend/.env.example` 为 `backend/.env`，**不要把 `.env` 提交 git**。

### 本地开发（已在用）

```env
DEBUG=1
SECRET_KEY=任意本地值即可
ALLOWED_HOSTS=127.0.0.1,localhost
CORS_ALLOWED_ORIGINS=http://127.0.0.1:6060,http://localhost:6060
CSRF_TRUSTED_ORIGINS=http://127.0.0.1:6060,http://localhost:6060
SQLITE_PATH=db.sqlite3
AI_PROVIDER=bailian
```

百炼、短信等键名见 `.env.example`，密钥只放服务器 `.env`。

### 生产必改

| 变量 | 要求 |
|------|------|
| `DEBUG` | 必须 `0` |
| `SECRET_KEY` | 一长串随机字符，不能再用 `replace-me` |
| `ALLOWED_HOSTS` | 域名和/或服务器 IP，不能是 `*` |
| `CSRF_TRUSTED_ORIGINS` | 带协议，如 `https://jiaoyan.example.com` |
| `CORS_ALLOWED_ORIGINS` | 一般与上面相同。H5 和接口同域时主要给管理后台用 |
| `SQLITE_PATH` | Docker 生产用 `/app/data/db.sqlite3` |

`DEBUG=0` 时若 `SECRET_KEY` 仍是占位符，或 `ALLOWED_HOSTS=*`，进程会直接拒绝启动。

生成密钥示例：

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

## 四、不用 Docker：Nginx + Gunicorn

适合已经装好 Nginx 的 Linux 主机。示例路径：`/var/www/jiaoyanyun`。

### 1. 后端

```bash
cd /var/www/jiaoyanyun/backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# 编辑 .env：DEBUG=0 及生产密钥、域名
python manage.py migrate --noinput
python manage.py collectstatic --noinput
```

用 systemd 跑 gunicorn（绑定本机 `8001`，不要把 8001 暴露到公网）：

```ini
# /etc/systemd/system/jiaoyanyun.service
[Unit]
Description=教研云后端
After=network.target

[Service]
User=www-data
WorkingDirectory=/var/www/jiaoyanyun/backend
EnvironmentFile=/var/www/jiaoyanyun/backend/.env
ExecStart=/var/www/jiaoyanyun/backend/.venv/bin/gunicorn config.wsgi:application --bind 127.0.0.1:8001 --workers 2 --timeout 300
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now jiaoyanyun
```

SQLite 并发不宜把 `--workers` 开太大，**2 个即可**。`--timeout 300` 是为了教案/报告流式生成。

### 2. 前端

```bash
cd /var/www/jiaoyanyun/frontend
npm ci
npm run build
```

打包后接口仍走相对路径 `/api`，由 Nginx 反代，**不必**设 `VITE_API_BASE_URL`。

### 3. Nginx

把 `deploy/nginx.host.conf` 拷到 `/etc/nginx/conf.d/jiaoyanyun.conf`，改 `server_name` 和 `root` / `alias` 路径，然后：

```bash
sudo nginx -t && sudo systemctl reload nginx
```

HTTPS：用 certbot 给该站点签证书即可，反代头里已带 `X-Forwarded-Proto`。

## 五、本机开发（不要当生产）

```bash
# 后端，必须 8001（Vite 代理写死默认值）
cd backend
.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8001

# 前端
cd frontend
npm run dev
```

- 教师端：http://127.0.0.1:6060  
- 管理后台：http://127.0.0.1:8001/admin/ （Vite 不代理 `/admin` 时用这个；已加上 `/admin` 代理后也可走 6060）

可选：`docker compose up --build` 起开发容器。容器内前端通过 `VITE_API_PROXY` 访问后端服务名，不要再用容器自己的 `127.0.0.1`。

## 六、上线核对清单

- [ ] `DEBUG=0`，`SECRET_KEY` 已更换  
- [ ] `ALLOWED_HOSTS`、`CSRF_TRUSTED_ORIGINS` 含真实域名（后者必须带 `http://` 或 `https://`）  
- [ ] 已执行 `migrate`、`collectstatic`  
- [ ] Nginx 能打开 `/`、`/api/auth/token/`、`/admin/`、头像 `/media/`  
- [ ] 生成教案/报告能等满 1～2 分钟（超时要 ≥300 秒）  
- [ ] `.env` 未进 git，80/443 对教师开放，**不要**把 `8001` 映射到公网  
- [ ] 定期备份 SQLite 文件和 `media/`（头像、上传件）  

本期仍用 SQLite，单校几十位老师够用。以后人多了再迁 PostgreSQL。
